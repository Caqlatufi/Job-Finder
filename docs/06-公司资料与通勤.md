# 公司资料与通勤

维护公司资料、办公点、通勤依据和公司质量；不负责JD正文识别、岗位评分或投递状态。与[JD管理与评分](05-JD管理与评分.md)协作，不把总部地址自动当作岗位办公点。

## 1. 需求分析

### 背景、目标与对象

公司属性、办公点和通勤会被多个 JD 复用。候选人维护一次，JD 收集和评分统一消费。

### v0.1 范围与核心需求

- 编辑、查看、搜索公司；保留已有公司录入接口，公司库不提供独立“新增公司”按钮。
- 维护名称、别名、业务属性、产品所有权、地址、通勤、质量和备注。
- 为 JD 提供公司选择和名称展示。
- 公司级官网投递渠道维护一次供多个 JD 复用；只填写核实过的官方招聘页或官网指向的招聘站，未确认留空，证据和邮箱记录在研究备注中。公司渠道存在不代表某条 JD 官网同步。

### 本期边界与能力边界

- 公司库以公司为独立对象。公司列表及地图公司卡片不提供“查看 JD”入口，不将岗位列表作为公司操作的必经流程；JD可作为地址证据来源，岗位管理仍从JD列表进入。
- 地图公司卡片展示公司名与地址；有详细地址时左侧标绿。当前收录有问题时改为黑色，并显示一行简短失败原因，黑色优先于绿色；重新排队或运行后清除旧原因，成功后恢复绿色。无单公司补全、继续、重试和独立匹配按钮，统一从右上角开始/停止。
- 不保存 JD、阶段、简历或面试。
- 公司库提供“公司列表 / 上海地图”切换，只展示上海市底图；支持同一公司维护多个工作地点，汇总公司办公地址与未删除 JD 的地点，不用总部地址覆盖岗位办公点。
- 底图随前端打包，无需地图 Key；收录流程自动通过 Photon 匹配已有详细地址的楼宇/园区，串行限速并缓存结果，页面不再提供独立匹配按钮。地址不完整时显示区域参考或待补充，不能把行政区中心伪装成具体办公楼；地图不计算通勤。
- 上海道路以本地 GeoJSON 随应用发布，保留真实道路折线、道路等级及路名；全市显示主干路，放大逐步显示街道和支路，可开关道路图层。道路仅绘制当前视野内的部分，拖动和缩放自动更新；等级规则保持。另提供独立的“地铁”开关，按真实WGS84坐标叠加线路，放大显示站点与站名。道路、地铁均离线显示，不请求在线地图或瓦片服务。
- 公司初评不覆盖岗位保存时的公司分。
- 不物理删除，停用后不供新 JD 选择。

### 后台范围与兼容策略

公司页提供搜索、编辑和上海地图，不提供独立新增公司按钮。列表按页读完全部公司，不能只取前100家。通勤基准与时间要求由本地 JD 门槛配置；办公点变化时维护多个工作地点并在备注保留背景，历史岗位不自动重算。

### 成功标准与工作量

资料可复用、名称不重复、范围合法、历史关联不丢失；预计 0.5–1 个开发日。

## 2. 架构设计

### 总体架构与链路

```text
frontend/company -> company Controller -> Service -> Repository -> jd_company
posting ----------------------------------------------------------^ companyId
录入 -> 标准化名称 -> 唯一性/范围校验 -> 保存 -> JD 选择
```

### 规则矩阵

| 规则 | 口径 |
| --- | --- |
| 名称 | 去空格后非空，忽略大小写唯一 |
| 通勤/质量 | 0–300 分钟；0–20 分 |
| 启用 | 默认 true；停用不破坏历史 |

### 核心数据模型

| 字段 | 类型 | 必填 | 用途/约束 |
| --- | --- | --- | --- |
| `name/alias` | String(120) | 名称是 | 正式名/简称 |
| `businessType` | Enum | 是 | PRODUCT、TO_B_PRODUCT、DELIVERY、OUTSOURCING、UNKNOWN |
| `productOwnership` | Enum | 是 | HIGH、MEDIUM、LOW、UNKNOWN |
| `address` | String(255) | 否 | 兼容原办公地址，地图与多地点一起去重汇总 |
| `workLocations` | List，最多50个 | 否 | 每项包含地点名称≤120、地址必填≤255、可选WGS84经纬度；经纬度必须同时填写 |
| `officialApplicationUrl` | String(2048) | 否 | HTTP/HTTPS 官方投递渠道，拒绝脚本链接和带账号的 URL |
| `commuteMinutes/qualityScore` | Integer | 否 | 0–300 / 0–20 |
| `notes` | Text | 否 | 路线、搬迁、业务研究 |
| `active` | Boolean | 是 | 新数据可选性 |

### 目录、职责与存储

图例：`[+]` 新增，`[~]` 修改，`[-]` 删除。

```text
backend/company/src/main/java/com/jd/company/{[~] ctrl,model,repo,service}
frontend/src/company/{[~] api,pages,index.ts}
```

公司主资料归属 `jd_company`，多地点按顺序存储于 `jd_company_work_location`，地图匹配缓存位于 `jd_company_location_cache`。均由 JPA DDL 管理；只新增 jd_ 表，不操作 aic_ 表，不使用迁移脚本。

## 3. 开发方案

### 目标、范围与顺序

交付公司 CRUD、搜索和 JD 选择：实体/Repository → Service 校验 → Controller → 公司页面 → JD 联动。

### 职责、边界与依赖

公司功能拥有公司数据和唯一性规则，依赖公共基础能力；posting 只通过 `companyId` 和公开查询交互，不在本功能处理岗位评分。

### 数据模型

保存字段：`name`必填≤120、`alias`≤120、`businessType/productOwnership`必填、`address`≤255、`commuteMinutes` 0–300、`qualityScore` 0–20、`notes`、`active`。响应增加 `id/createdAt/updatedAt`。

新增可选 `officialApplicationUrl`≤2048：去首尾空格，空字符串清空；旧客户端遗漏或传 null 时保留现有链接。公司页支持编辑与打开官方招聘，JD 列表按 `companyId` 复用该链接。该字段不替换岗位 `sourceUrl`，不修改 `officialSynchronized` 或投递阶段。

`workLocations` 在旧客户端遗漏或传 null 时保持原值，显式 `[]` 清空多地点；原 `address` 字段独立兼容。公司保存事务同时更新多地点，非法数据不得部分落库。上海地图汇总三类来源：手动工作地点、原公司地址、JD地址；同公司相同地址合并来源，不同办公点分别保留，仅写“上海”的重复市级记录不额外冒充办公点。

地图坐标优先使用显式WGS84标注，其次使用楼宇/门牌名匹配结果；坐标经上海行政区多边形校验，外地地点隐藏。底图采用正北朝上的二维墨卡托投影，按投影比例居中适配画布，不随宽高拉伸；行政区边界、地点标记和公司聚焦统一使用同一投影。仅知道区名的地址使用灰色菱形区域参考；没有区名且未能匹配的地址进入待补充清单，不补造经纬度。重合点合并显示地点数，点击可查看组内所有地点；点击公司可以突出其多个办公点。支持公司/地址搜索、行政区筛选、定位状态筛选、拖拽缩放及全上海复位。

Photon 外部请求单线程、间隔至少1100毫秒；成功结果缓存，空结果缓存7天，网络失败不记为成功。只接受上海州/市范围内且名称或街道门牌匹配的结果，前端再次检查上海市界；匹配地点是参考结果，不代表招聘方确认。可通过 `jd-collector.company.geocoder-url` 切换自建 Photon 兼容服务。外部请求期间不持有数据库事务，页面关闭后停止后续队列，失败时保留离线底图与区域分布。

本地道路来自 [Geofabrik 上海 OSM SHP 数据](https://download.geofabrik.de/asia/china/shanghai.html)，生成文件为 `frontend/src/company/assets/shanghai-roads.geojson`，按上海区划边界裁剪，使用 WGS84 经纬度，约一米容差简化折线。仅包含已有的可驾车道路分类，不臆造道路，不将街道办事处边界或地址文字转换成虚构道路。配套 `shanghai-roads.metadata.json` 保存来源、归档时间、SHA-256、道路分类数量和 ODbL 许可；页面保留 [OSM 署名与许可链接](https://www.openstreetmap.org/copyright)。它是显示数据，不包含路线计算所需的完整通行限制与拓扑。

道路按缩放倍数分级：小于2显示高速/快速路/主要干道，2起增加次干道，5起增加普通街道，10起增加支路；空间索引仅查询当前视口边界内相交的道路，不再多查半屏缓冲区；使用Liang–Barsky逐段裁剪到视口，只把可见折线提交画布，保留穿越视口的长边并分离离开后再进入的路径。投影坐标继续缓存，四个道路路径继续共享仿射变换，拖动逐帧平移、最多每150毫秒重查并裁剪一次，避免恢复全量逐道路布局。路名在屏幕空间去重和避让公司标记，最多45个，滚轮、拖动、窗口缩放、聚焦公司及“全上海”复位后同步更新。道路不可点击，不拦截公司标记；公司搜索不会隐藏道路。道路加载失败显示独立重试入口，不阻断公司地点与行政区底图。

更新数据时，在项目根目录使用独立 Python 环境安装 `ops/maps/requirements.txt`，执行 `python ops/maps/build-shanghai-roads.py --download`；原始压缩包存放 `runtime/maps`，不提交。已有压缩包可省略 `--download`，也可通过 `--source <zip路径>` 指定归档。生成后执行前端构建和道路/地点 Electron 验收，再打包本地服务。日常打开地图不运行生成脚本。

地铁来源为 [OSM Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API) 的上海地铁 route 关系及停靠节点；按 network:en=Shanghai Metro、route=subway/light_rail 选择，排除其他城市、机场内部捷运和建设/规划/废弃关系。保留线路颜色及各独立way几何，不以站点直线连线冒充真实走向；按OSM way ID去重同线重复关系，站点按同名且邻近合并换乘线路。当前本地快照包含1–18号线与浦江线，共19条线路、414个站点，OSM基准时间2026-11-06；并非官方实时运营图。`frontend/src/company/assets/shanghai-metro.geojson`与`.metadata.json`保存线路/站点、原始关系/节点ID、查询语句、时间、SHA-256与ODbL许可。地铁默认关闭，首次开启加载本地文件，关闭后保留缓存；每线一个缓存路径，按当前视口裁剪，线路位于道路上层、公司标记下层，缩放3倍起显示站点，站名避让公司标记且与线路标签合计最多40个，路名避让地铁标签。拖动、缩放、聚焦、复位和改变尺寸同步更新，失败单独重试，不影响其他图层。更新执行`python ops/maps/build-shanghai-metro.py --download`，原始响应保存在忽略目录`runtime/maps/`；离线重生成可省略`--download`。

### 公司地址补全

地图公司卡片展示公司名、地址及当前失败时的一行中文原因，不显示机器码、来源标签、证据展开或历史统计。已有详细地址左侧默认4px绿色；FAILED/OPTIMIZATION_PENDING/NOT_FOUND及历史待核对终态使用黑色，位置匹配失败也标黑；仅停止不作为失败。失败原因按截图、页面加载、登录/验证、地址确认或位置匹配等实际错误归类。任务重新排队/运行后清除旧提示，成功后恢复绿色。右上角只保留“剩余未收录 N 家”和开始/停止，进度按当前地址与位置动态计算，不展示历史批次总数、进度条、成功/跳过统计或完成说明；0家禁用开始。轮询按taskId、attempt及终态更新页面，包含地址已保存但定位失败的结果，防止同任务重跑后不刷新。后台持续执行，返回页面恢复当前状态；仍使用LangGraph及FileCheckpointer，不弹进度窗、不要求人工继续/单任务重试。

批次保存于`runtime/company-addresses/batch.json`。完成口径为：公司至少有一个上海详细地址，且其全部上海详细地址都有显式有效坐标或成功的缓存坐标；仅城市/行政区不算地址，空匹配缓存不算定位成功。后端汇总有效公司、多工作地点、未删除JD和地址证据，按标准化地址去重，排除停用和只有外地地点的公司。GET `/company-address-tasks/companies/{companyId}/plan`提供公司、全部详细地址及尚待定位地址，批次计数与worker使用同一计划。没有地址先查询最新JD及公司来源，已有地址直接串行定位，不重新开页面。`unrecorded`始终统计缺详细地址或仍有未定位地址的公司，一公司只计一次；历史批次数量仅作快照。按公司ID顺序处理，已有运行/排队任务复用；用户明确开始新一轮时，将仍未完成公司的历史失败、优化待办、未找到及停止任务重新排队一次，保留taskId、检查点、原尝试及优化任务，已成功但新增待定位地址时创建当前任务。批次内部不自动循环重试同一失败。并发开始复用同一RUNNING批次，先持久化PREPARING、准备完整列表后再RUNNING，停止不再派发下一项。

停止先持久化`STOPPING`关闭派发，再向当前尝试写`stop.requested`。worker每个节点及原生动作/接口前检查信号，模型子进程支持取消；当前已提交的写入仍以已保存事实为准，不删除地址或证据。停止不是流程缺陷，不生成优化任务，当前尝试结束为`STOPPED`，再开始时保留历史并新建尝试。停止/进度回读及调度共享队列同步锁，停止后不会抢先启动下一家公司；后台与页面重启后保持批次状态。

地址任务成功、异常或停止后，在`finally`关闭与任务ID一致的`company-address:<uuid>`标签；JD链接收录同样只关闭自己打开的`jd-import:<uuid>`标签。未执行打开动作时不关闭标签，固定工作台、普通平台页和用户标签均保留。关闭失败留日志，地址流程额外生成优化任务；原生PNG与检查点不受关闭影响，开发重放会重新打开任务页。

同公司只保留一条当前任务。`OPTIMIZATION_PENDING`、`NOT_FOUND`及历史失败/暂停状态仍参与去重；新流程不生成等待人工处理的中断，历史检查点保留兼容。修复后开发侧通过既有retry接口重放原任务，保留任务ID、后台标签、检查点和全部历史日志，仅下一次执行增加尝试次数。成功且已收录地址后不再提供重复补全入口。已有重复记录保留全部文件及尝试证据：正在执行的任务优先作为当前任务，否则取创建时间最新的任务；其他未完成记录标记为 `SUPERSEDED`，记录原状态与当前任务ID，退出调度和列表。成功的历史记录保留成功状态。

并发实现方式：创建、重试、列表和调度均在本地单个后端的队列服务同步锁内读取、合并与写入；调度继续使用文件锁，并先核对全部工作进程存活状态。合并不终止存活的工作进程；同公司排队/暂停记录不会再次启动重复工作。每次尝试的完成文件只更新所属任务，原任务与检查点均保留。其他公司使用独立分组，JD收录队列继续遵循原有规则。

先使用该公司最新收录的一条未归档JD（`createdAt DESC,id DESC`，与评分排序无关），逐页截图找该岗位的详细工作地址，不顺次扫描旧JD。最新JD没有可用链接，或当前链接已记录关闭时，直接查询公司在上海的办公地址。新识别到JD明确关闭、页面失效、描述折叠无法读取或完整页面无详细地址时，将获取结果、原因、核对时间、原链接与截图证据记录到该JD，并转入公司地址搜索；这些情况本身不将公司标为失败/待核实。公司地址搜索仍有歧义时记录优化任务；全部正常来源均没有详细地址时记录NOT_FOUND。关闭判定必须有当前公司、岗位及关闭提示的截图证据，不能把登录、验证码、推荐岗位关闭或页面打不开推断为JD关闭。JD证据必须对应当前公司和岗位；公司搜索结果保留为公司地址参考，不能作为该JD的工作地址。只知道城市/行政区、仅有注册地址、公司身份不确定或地址冲突时记录优化任务并尝试后续来源，不猜测门牌或经纬度。

地址证据存储于 `jd_company_address_discovery`，包含公司/岗位、地址、来源URL、截图证据引用及任务ID。同公司同岗位同地址幂等保存，不覆盖公司原资料和其他办公点；经核实的JD地址仅更新该岗位的 `location`，保存时核对原链接和原地址，其他评分、正文与阶段保留。地图合并来源，原接口保留地址证据供开发侧核对。地址保存并回读后必须进入position节点，串行匹配位置并GET缓存回读确认；多地址逐一完成，不要求再次点击其他按钮。仅全部地址位置确认后为SUCCEEDED；空匹配、调用失败或位置回读不一致为OPTIMIZATION_PENDING，保留已保存地址、缓存及证据，日志先于去重优化任务。停止检查覆盖每个API与下一个地址，不回滚此前确认的事实。

批次接口：`GET /api/company-address-tasks/batch`、`POST /api/company-address-tasks/batch/start`、`POST /api/company-address-tasks/batch/stop`，无公司ID请求体，后台统计全部候选并维护进度。保留开发侧单任务接口：`POST /api/company-address-tasks {companyId}`，`GET /api/company-address-tasks`、`GET /api/company-address-tasks/{id}`、`POST /api/company-address-tasks/{id}/retry`；证据读取 `GET /api/companies/address-discoveries`，公司参考写入 `POST /api/companies/{id}/address-discoveries`，岗位地址写入 `POST /api/postings/{id}/address-discoveries`。队列位于 `runtime/company-addresses`；不是新的数据库任务系统。地址后台标签采用 `company-address:<uuid>`，需客户端 `WEB info` 返回 `companyAddressCapture=true`；旧客户端能力不足时记录优化任务并结束本次查询，不要求用户当场介入。

异常分支采用“日志 → 优化任务 → 安全回退或结束”的顺序：每次发生先追加到当前attempt的`branch-events.jsonl`，再在`local/workflow-optimizations/wf-<指纹>/`生成`TASK.md`、`task.json`与独立`events/<uuid>.json`。指纹按工作流、节点、错误码、来源类型和站点去重；并发及重复尝试只追加发生记录，不覆盖已有任务单。发生记录含任务/公司/岗位标识、节点、错误码、实际模型动作、原生截图引用及哈希、检查点引用，URL去除凭据、query和hash，不复制原始异常堆栈或会话秘密。

模型协议非法、无效滚动、登录/验证码、截图失败、来源歧义及未覆盖异常均留任务单。尚未写地址的节点可尝试下一来源，所有可用来源结束后为`OPTIMIZATION_PENDING`，队列自动处理下一家公司；地址保存/回读存在不确定性时直接结束本任务，不转其他来源继续写入。地址已经保存但必需的位置匹配失败时保留地址，任务为OPTIMIZATION_PENDING并记录具体位置原因，自动继续下一家公司。只有完整页面确实无地址且没有流程异常时为`NOT_FOUND`，不把正常业务结果伪装成流程缺陷。任务单写入失败时保留日志并返回真实`FAILED`，不得声称“已记录优化任务”。任务单由后续开发修复，运行中Agent不自行修改代码或绕过网站验证。

底图来源：[阿里云DataV上海行政区GeoJSON](https://geo.datav.aliyun.com/areas_v3/bound/310000_full.json)，仅包含上海16区；地点数据注明 © OpenStreetMap contributors / Photon。匹配服务使用限制见 [Photon项目说明](https://github.com/komoot/photon#demo-server)，保持低频本机单用户用途，不批量抓取整个城市POI。

路网可视范围使用与绘图相同的仿射变换反算经纬度，避免ECharts 5.6自定义投影下`convertFromPixel`反算顺序错误导致道路被全部筛掉；保留空间索引、四个缓存路径及拖动时只移动图层的优化。验证同时核对道路像素、路名、分级缩放、开关及窗口尺寸变化，不能仅用“文件加载成功”代替可见道路。
